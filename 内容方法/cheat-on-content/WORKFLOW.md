# cheat-on-content 的工作台适配约定

工作台流程：手动点击后结合当下热点、之前的视频内容和真实评论想选题；只有点击某一条“展开拍摄方案”后才写具体口播与镜头。小红书与 X 直接提炼已经拍摄的视频，输出可以直接发布的中文正文。

采用 cheat-seed、cheat-trends、cheat-recommend 的选题方法，并根据当前工作台流程适配：

1. 围绕真实资料中的兴趣、观众问题或已有主题寻找新角度。热点仅作线索，要有来源和获取时间，不强行关联，不把热度当作事实。
2. 排除已拍摄、不感兴趣及同批重复内容。推荐理由要能追溯到所提供的作品、评论或热点。
3. 通常提供一条“延续”、一条“探索”、一条“备选”。“延续”只表示与历史主题自然衔接，不暗示流量稳定；无历史时可全部标为探索。没有合理实验角度时，不为凑数虚构实验。
4. 每条给出 strategy 和 testHypothesis。testHypothesis 只用一句话说明想验证的受众需求或内容角度，不能包含口播、镜头、材料和具体操作步骤。reason 说明为什么值得做；difference 对比真实历史内容，无可比样本时直说。
5. 只按可见证据做质性评估：观点是否具体、与已有内容是否相关、是否回答真实问题、是否有新角度、依赖信息是否足够。不要临时创造数字分数或把一条历史作品称为成功样本。
6. 初始方向未定；当前方向始终以工作台最新设置为准。尚无个人校准数据，暂不使用观点类视频的七维评分，也没有校准后的爆款概率或播放量预测。此适配不等同于运行完整 cheat-score / cheat-predict / cheat-retro 流程。
7. 脚本或发布文案按素材最强信息选择结构，不能所有稿件都套同一个三段式。不为增强开头编造数据、经历、效果、讽刺或比喻。必要条件和事实边界保留。
8. 已拍视频的改写仅提炼实际内容；不把题材探索、评分、写作分析或未来拍摄方案混进小红书和 X 的发布正文。真正不确定的信息单列在待确认项中。

应用每次生成会读取随项目提供或明确配置的相关技能文件，并保存采用的文件摘要值，用于辨别以后技能发生的变化。正式资料仍只存于工作台 data/library.json，既有版本和用户反馈继续保留。本目录不复制用户作品，不自动建立预测、发布或复盘日志，也不开启定时任务。
